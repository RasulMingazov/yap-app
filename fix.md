Рефакторинг авторизации и UI
1. Вынести цвета в общую тему
   Сейчас часть цветов захардкожена непосредственно на экране логина.
   Необходимо:
   Перенести цвета экрана авторизации в общую тему приложения.
   Убрать захардкоженные значения из UI-компонентов.
   Использовать семантические названия цветов, соответствующие их назначению.
   Обновить цвет Snackbar в тёмной теме: теперь он должен совпадать с цветом в светлой теме.
2. Расширить AuthProvider
   Добавить в AuthProvider параметры:
   enum class AuthProvider(
   val isVisible: Boolean,
   val isEnabled: Boolean,
   )
   Ожидаемое поведение:
   isVisible определяет, показывается ли провайдер пользователю.
   isEnabled определяет, доступен ли провайдер для выбора.
   Управлять доступностью и видимостью провайдеров можно в одном месте.
   UI не должен самостоятельно хранить эти настройки.
3. Сделать единый LoginUseCase
   Вместо передачи во ViewModel всех вариантов авторизации нужен единый use case:
   LoginUseCase(authProvider)
   Требования:
   ViewModel знает только о едином LoginUseCase.
   ViewModel не должна иметь доступ к коллекции всех способов авторизации.
   Конструкция вида:
   loginUseCases: Map<AuthProvider, LoginUseCase>
   не должна находиться во ViewModel.
   Определение конкретного сценария авторизации выполняется внутри domain/data-слоя.
   Архитектура не должна быть завязана исключительно на Google.
   Добавление нового провайдера не должно требовать изменений во ViewModel и основном экране логина.
   Следует предусмотреть понятный механизм регистрации обработчиков разных провайдеров.
4. Вынести выбор провайдера в отдельный Bottom Sheet
   Создать отдельный экран, например:
   SelectAuthProviderBottomSheet
   Он должен отвечать за:
   отображение доступных способов авторизации;
   обработку выбора провайдера;
   состояния видимости и доступности;
   отображение названия, иконки и других UI-данных провайдера.
   Для Bottom Sheet необходимо сделать собственные:
   UiState;
   UiStateMapper;
   при необходимости отдельную ViewModel.
   После этого нужно упростить основную LoginViewModel, убрав из неё логику, относящуюся непосредственно к выбору и отображению провайдеров.
5. Убрать AuthProviderCatalog
   Текущий AuthProviderCatalog выглядит как лишняя и недостаточно понятная абстракция.
   Предлагаемое изменение:
   Удалить AuthProviderCatalog, если после рефакторинга в нём больше нет необходимости.
   Формировать UI-модели провайдеров в UiStateMapper экрана выбора.
   Именно mapper должен сопоставлять AuthProvider с иконкой, названием и остальными UI-данными.
   Не допускать утечки UI-ресурсов в domain/data-слой.
6. Исправить анимацию Snackbar
   Сейчас Snackbar при скрытии просто исчезает через fade-анимацию, что визуально не соответствует ожидаемому поведению.
   Необходимо:
   Проверить рекомендуемый способ отображения Snackbar в Compose Multiplatform.
   По возможности использовать стандартный механизм CMP/Material, а не вручную собранную анимацию.
   При исчезновении Snackbar должен уезжать вверх, а не только менять прозрачность.
   Корректно обработать появление, автоматическое скрытие и последовательное отображение нескольких сообщений.
7. Почистить data-слой
   Провести ревью data-слоя авторизации и найти:
   излишне многословные конструкции;
   повторяющийся код;
   ненужные обёртки и промежуточные модели;
   интерфейсы, у которых только одна реализация и нет понятной причины существования;
   лишние преобразования данных;
   код, завязанный исключительно на Google-авторизацию.
   Перед рефакторингом сначала подготовить краткое предложение:
   Какие части предлагается изменить.
   Почему текущий вариант избыточен.
   Как будет выглядеть упрощённая структура.
   Какие компромиссы или риски есть у изменений.
   После этого обсудить предложение со мной и только затем существенно переделывать data-слой.
   Критерии готовности
   На экране логина нет захардкоженных цветов.
   Цвет Snackbar одинаковый в светлой и тёмной темах.
   Видимость и доступность провайдеров задаются через AuthProvider.
   Основная LoginViewModel использует только единый LoginUseCase.
   Во ViewModel отсутствует Map<AuthProvider, LoginUseCase>.
   Добавление нового провайдера не требует изменения основной LoginViewModel.
   Выбор провайдера вынесен в отдельный Bottom Sheet.
   UI-данные провайдеров формируются в mapper-е Bottom Sheet.
   AuthProviderCatalog удалён либо его необходимость убедительно обоснована.
   Snackbar скрывается с корректным движением вверх.
   Перед рефакторингом data-слоя представлен отдельный план изменений.
